# Агентные системы в бизнесе: проект desk

Код к семинарам курса «Агентные системы в бизнесе», ВШЭ, 2026.

За семестр мы строим одну систему: службу поддержки платёжного сервиса «Лира».
Клиенты пишут в поддержку, а система разбирает обращения, ищет ответы в
регламентах, проверяет платежи и передаёт сложные случаи человеку. На каждом
семинаре в проекте появляется новая часть: сначала выкладывается заготовка,
после занятия решение.

## Как запустить

Нужны `uv` и личный ключ шлюза курса. Проект использует Python 3.13.

```bash
uv sync
cp .env.example .env
```

В `.env` впишите свой ключ в строку `LLM_API_KEY=`. Ключ выдаёт
преподаватель, у каждого он свой и с дневным лимитом. Не выкладывайте его:
файл `.env` уже в `.gitignore`.

У ключа есть и лимит 10 запросов в минуту. Клиент сам выдерживает паузы по
строке `LLM_RPM=10` в `.env`, поэтому замер четырёх кандидатов на 30 обращениях
идёт около двенадцати минут, а задержка в таблице считается без ожидания.

Тесты работают без ключа и без сети:

```bash
uv run pytest tests
uv run ty check
uv run ruff check .
uv run ruff format --check .
```

`ty` проверяет код двух домашних заданий и инструменты замера, `ruff` проверяет
все файлы Python.

Профиль памяти одного короткого прогона:

```bash
mkdir -p runs
LLM_CACHE_DIR= uv run memray run -f -o runs/escalation.bin -m desk.escalation --split dev --n 5
uv run memray stats runs/escalation.bin
uv run memray stats --json -f -o runs/escalation.json runs/escalation.bin
uv run memray flamegraph -f --no-web -o runs/escalation.html runs/escalation.bin
uv run python tools/memory_chart.py runs/escalation.json assets/memory.png
uv run python -m tools.leak_probe
```

Трасса и интерактивный график остаются в `runs/`. Для сравнения памяти
нескольких запусков используйте одинаковое число обращений и настройки.

## Как получить новый семинар

Работайте в своём форке этого репозитория. Заготовка каждого нового семинара
появляется здесь перед занятием, и её подтягивают в форк так:

```bash
git remote add upstream https://github.com/paNikitin/asbiz.git   # один раз
git pull upstream main
```

Если вы меняли в форке те же строки, что изменились в заготовке, git попросит
разрешить конфликт вручную.

## Что где лежит

- `desk/`: код проекта.
- `tests/`: тесты.
- `data/`: обращения клиентов с правильной разметкой и правила разметки.
- `runs/`: сюда скрипты сохраняют результаты замеров.

## Семинары

### Семинар 1. Клиент к модели и замер кандидатов

- Отправили запрос к модели вручную и посмотрели, из чего состоит ответ:
  блоки, причина остановки, счёт токенов (`1_raw_request.py`).
- Написали клиент `desk/llm.py`. Через него идут все вызовы модели: он
  повторяет запрос при сбоях, считает токены и деньги, хранит кэш ответов.
- Добавили потоковую выдачу (`desk/stream.py`) и научились мерить время до
  первого токена.
- Проверили, как положение даты в постановке влияет на кэш у провайдера
  (`3_prefix_cache.py`).
- Сравнили на 30 обращениях четыре способа поставить модели задачу: короткую
  постановку, постановку с правилами, те же правила с рассуждением и с примерами
  (`desk/bench.py`). Выбор кандидата записывается по шаблону
  `выбор_шаблон.md`.

```bash
uv run python 1_raw_request.py
uv run python 3_prefix_cache.py
uv run python -m desk.bench --n 30
```

пометкой, нужен ли человек. Схема проверяет, что модель ничего не выдумала.
